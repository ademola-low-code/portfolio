Your business receives customer enquiries through at least three different channels: your website form, your main contact email, and your WhatsApp Business line. Right now, these messages live in three separate places. Someone has to check the inbox, read the form notification emails, scroll through WhatsApp chat logs, and manually paste details into a sheet or CRM.

When you do this manually, three things happen. First, enquiries drop through the cracks during busy shifts. Second, response times drag out from minutes to hours. Third, you have no single source of truth to see how many new leads actually came in this week.

The goal is simple: log every enquiry into one central sheet automatically, regardless of where it came from, with the same structure, in real time. Here is how to build this system properly using n8n.

## The Architecture: Three Triggers, One Master Format

The biggest mistake people make when centralising data is building separate automation workflows for each channel that write to a database in different ways. That creates inconsistent data. 

Instead, you use a single n8n workflow with multiple trigger nodes, or standardise the incoming payload early so that every lead hits your spreadsheet looking identical.

Your central log needs six core columns:
1. **Timestamp** (ISO standard format)
2. **Channel** (Web, Email, WhatsApp)
3. **Contact Name**
4. **Contact Detail** (Email address or phone number)
5. **Message / Enquiry**
6. **Status** (Default to "New")

Here is how the data flows from each source.

## Step 1: Capture Web Forms Instantly

If you use Elementor, Typeform, Tally, or custom HTML forms, do not rely on email notifications as your trigger. Webhooks are faster and do not break when an email server alters the formatting.

1. Add a **Webhook Trigger** node in n8n. Set the HTTP Method to `POST`.
2. Copy the Webhook URL generated by n8n.
3. Paste this URL into your form builder's webhook setting.
4. Send a test submission.

In n8n, you will receive a JSON payload. Use a **Edit Fields (Set)** node immediately after the webhook to map the form fields to your standard structure:

```json
{
  "timestamp": "={{ $now }}",
  "channel": "Web Form",
  "name": "={{ $json.body.first_name }} {{ $json.body.last_name }}",
  "contact": "={{ $json.body.email }}",
  "message": "={{ $json.body.message }}",
  "status": "New"
}
```

## Step 2: Route Incoming Emails Without Reading Spam

For email enquiries (e.g., `info@yourcompany.com`), use the **Gmail** or **Microsoft Outlook** node with an event trigger for *On New Email Received*.

To prevent logging internal updates, newsletters, or spam, apply a filter immediately after the trigger:
- Exclude messages where the sender domain matches your own company domain.
- Exclude messages containing headers like `List-Unsubscribe`.
- Only capture emails sent directly to your sales or support address.

Pass the filtered output to an **Edit Fields** node:

```json
{
  "timestamp": "={{ $json.date }}",
  "channel": "Email",
  "name": "={{ $json.from.name || $json.from.address }}",
  "contact": "={{ $json.from.address }}",
  "message": "={{ $json.snippet }}",
  "status": "New"
}
```

## Step 3: Capture WhatsApp Messages

If you use Meta's Cloud API or a service like Twilio, add the corresponding trigger node. When a customer sends a message to your business number, Meta sends a webhook payload containing the sender's phone number, profile name, and message body.

Map this payload in a third **Edit Fields** node:

```json
{
  "timestamp": "={{ $now }}",
  "channel": "WhatsApp",
  "name": "={{ $json.entry[0].changes[0].value.contacts[0].profile.name }}",
  "contact": "={{ $json.entry[0].changes[0].value.messages[0].from }}",
  "message": "={{ $json.entry[0].changes[0].value.messages[0].text.body }}",
  "status": "New"
}
```

## Step 4: Normalise and Deduplicate

Connect the outputs of all three **Edit Fields** nodes into a single downstream branch. 

Before writing to your database, you must deduplicate. Customers often fill in a form, panic when they do not get an immediate answer, and send a WhatsApp message 60 seconds later.

Use an n8n **Google Sheets** (or **Airtable**) node set to **Append or Update Row**:
- **Column to match on**: `Contact Detail` (Email or Phone number).
- If the contact exists and their status is already marked as "In Progress" or "Resolved", update the `Message` column by appending the new text rather than creating a duplicate lead row.
- If the contact does not exist, append a new row.

When I built *StayEase*, a guest-request system running on n8n and Google Sheets, using standard HTTP triggers and clean deduplication meant handling hundreds of requests across multiple properties without paid database infrastructure or missing records.

## What Usually Goes Wrong

Building the basic flow takes under an hour. Keeping it reliable when real humans interact with it takes a bit more care.

### 1. Webhook Payloads Changing Without Notice
Form plugins frequently update their output structure during plugin updates. If your web form sends `user_email` on Monday and changes to `email_address` after a update on Tuesday, your workflow will start writing blank email fields to your spreadsheet.
*Fix:* Add an n8n **If** node that checks if the contact field is empty before writing to the sheet. If it is empty, route the payload to an error alert on Slack or email so you spot the broken field mapping immediately.

### 2. Formatted Phone Numbers Breaking Deduplication
A user enters `07123 456789` on your website form, but WhatsApp sends their number as `447123456789`. Your sheet will treat them as two different customers.
*Fix:* Strip all non-numeric characters using a short regex replace in a Code node: `{{ $json.phone.replace(/\D/g, '') }}`. Convert local numbers to international format before matching.

### 3. Media Messages Crashing the Flow
On WhatsApp or email, customers frequently reply with images, voice notes, or PDF attachments instead of plain text. A pipeline built solely for string fields will fail when `$json.text.body` comes back as undefined.
*Fix:* Use fallback logic in your expressions. For example: `={{ $json.message || '[Media File Received]' }}`. 

When I built a Twilio MMS-to-email pipeline for an Australian marketing agency, handling media attachments properly meant checking for media headers before processing text streams. If an attachment exists, upload it to a cloud bucket (or Google Drive) and log the public link in the sheet alongside the text.

### 4. Rate Limits on High-Volume Days
If you run a ad campaign and receive 50 web forms in two minutes, Google Sheets API will temporarily throw a `429 Too Many Requests` error. n8n will drop those executions unless configured to handle retries.
*Fix:* Open the settings tab on your Google Sheets node in n8n. Toggle **Retry on Fail** to ON, set Max Tries to `5`, and set Wait Between Tries to `5000` ms.

## The Limits of a Master Sheet

A single Google Sheet or Airtable base is the right place to start for up to roughly 2,000 enquiries a month. It gives your team immediate visibility without the overhead of learning a full CRM.

However, a spreadsheet is not a ticketing system. Once multiple team members start replying to enquiries directly from their own phones or personal email accounts, you lose track of who responded to what. 

At that point, keep the n8n ingestion logic you just built, but swap the final Google Sheets node for an API call to a proper inbox tool like Crisp, Hubspot, or Zendesk. The workflow structure remains identical; only the storage location changes.
